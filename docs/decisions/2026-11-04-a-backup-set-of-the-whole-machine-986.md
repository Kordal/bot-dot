2026-11-04: A backup set of the whole machine (#986) reads each account's files from its disk as root, not through a container of its rootless Docker as the ticket said, and writes their owners as that Docker sees them with GNU tar's `--owner-map`/`--group-map` (the account's user is 0, its sub-IDs 1 to 65536). A suspended account's Docker isn't running, and starting it would start its server and its bots; read from the disk, it is in the set too, and a running computer is never touched. The restore writes through the new account's own Docker, so the owners land on whatever sub-IDs the new machine gave it.
