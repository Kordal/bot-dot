2026-11-23: A pull request that changes nothing the installer reads skips the installer's tests (`test/installer*.test.js`), because they spent about 5,300 of the server tests' 7,800 seconds in CI (the biggest file alone, `installer.test.js`, 12 minutes, which no sharding can split), and a pull request's `server-tests` took 15 to 16 minutes where it takes 4 to 5 without them (measured on two machines, before the four of [2026-11-23](2026-11-23-the-server-tests-run-on-four-machines.md)). The `changes` job of `tests.yml` says which pull requests read the installer (`INSTALLER_PATHS`: `install.sh`, the compose files, the `Dockerfile`, `.dockerignore`, and the `lib/` files the installer tests load, which `test/ci-installer-filter.test.js` re-derives from the tests and from `install.yml`'s `paths:`), and `BOT_DOT_SKIP_INSTALLER_TESTS=1` makes `test/run.js` leave the files out (`make test` runs everything, unset). The safety net: a pull request that changes any of those runs them all, and `install.yml` runs the real install on it; every run that is not a pull request (the image build's call of `tests.yml`, by hand) runs the whole suite before images publish. Rejected: splitting `installer.test.js` into smaller files (the other ~4,500 seconds stay), and a daily run of the installer tests alone (a break would be found a day later, by someone else's pull request).
