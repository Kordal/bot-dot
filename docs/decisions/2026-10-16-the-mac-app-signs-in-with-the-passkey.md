2026-10-16: The Mac app signs in with the passkey on the front door's own page in an `ASWebAuthenticationSession` sheet, which hands the sign-in back as a one-time code at `botdot://signed-in`; the app turns the code into its session with a secret whose SHA-256 the page carried (`POST /sign-in/handoff`), so a code seen by anything else signs nobody in. Rejected: Apple's native passkey sheet (`ASAuthorizationPlatformPublicKeyCredentialProvider`), which needs the app signed with a developer team and an associated domain served over HTTPS: the app is built ad hoc for the owner's Mac (ADR 022), and the Mac's local botdot server is `localhost`. The session's secret is kept per botdot address in a file only the user can read (`~/Library/Application Support/dev.botdot.mac/sessions.json`), not the Keychain, for the reason the registry token isn't.
