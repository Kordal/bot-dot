2026-11-03: The server logs what holds it up (`lib/held.js`): every broker `callSync` and every memory.db statement is timed, one of 200 ms or more (`BOT_DOT_SLOW_SYNC_MS`) is a `[held]` line with what it was (operation, principal, file or SQL) and the code that asked, and a timer every 250 ms says `[lag]` when the event loop came back 500 ms or more late (`BOT_DOT_LAG_WARN_MS`), with the slow calls inside that time and the last request. A timer rather than `perf_hooks.monitorEventLoopDelay`, whose histogram says that the loop was held but not when, so a held loop couldn't be matched to the calls inside it. It is for the hq freezes (0.3 to 55 s on 10 to 20% of even `/api/health`): measure first, then move what the log names off the request paths.
