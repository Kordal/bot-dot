2026-11-06: The installer pins gVisor's `runsc` (`GVISOR_RELEASE` in `install.sh`): its apt source names one release (`.../gvisor/releases 20261102 main`) instead of the moving `release` channel, and a fresh install asks apt for `runsc=<release>`. runsc is the sandbox of every account, so a new release now comes with a botdot change, tested by `make install-real` and the gVisor test, which download the same release by sha256. An update moves an older machine's source to the pinned release and, when its runsc is of another release, says the command that installs the pinned one, but does not run it: replacing runsc under the accounts' running sandboxes could leave a running container with a runsc of another release. Tailscale stays unpinned on purpose: it is the machine's way in from the tailnet, and its fixes should arrive with `apt upgrade`. Rejected: `apt-mark hold runsc` (it leaves the moving source in place and a later `apt-get install runsc` jumps to the newest).
