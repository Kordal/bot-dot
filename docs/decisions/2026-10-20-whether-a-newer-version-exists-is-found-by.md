2026-10-20: Whether a newer version exists is found by root's step, as it writes the load, at most once an hour (a stamp in its runtime folder, so a check that fails waits its hour too), with the same signed release check an update makes, and written to `front-door/status/latest.json` as the release's source revision; an install or update writes the version it installed there. An update whose checked images are the ones the front door's and every running account's `.env` pin and their compose services run (`docker ps`) ends before it downloads or restarts anything. Rejected: the front door asking the registry (it never reaches the network for the machine, and the check needs root's copy of the release key), comparing pins alone (a failed update leaves the new pin beside the old container), and comparing release version numbers (version.json has only the revision).
