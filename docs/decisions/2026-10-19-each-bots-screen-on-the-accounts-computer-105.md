2026-10-19: Each bot's screen on the account's computer (#105, ADR 035) is a number from 1 to 89 that botdot keeps in `data/computer-screens.json`, gives a bot on its first computer call (the lowest free one) and frees when the bot is deleted; the Docker helper gets it in every call as the bot's seat, `{ bot, screen }`, and keeps nothing. Screen n is X display `:(10 + n)`, with VNC on 5900, noVNC on 6100, cua's computer-server on 8100 and the Camoufox bridge's port on 47200 plus the display's number, and its bridge socket `/run/botdot-browser/bridge-<display>.sock`, so no screen meets the shared screen of #104 (`:1`, 5901, 6001, 6080, 8000, 47111), which a running computer may keep until it stops. Each screen is a supervisord of its own (`deploy/desktop/botdot-screen.conf`) with the screen in its environment, without cua's driver MCP on port 3000, which botdot never used. Camoufox keeps a profile per bot id (`/home/browser/profiles/<bot>`), removed with the bot, so a bot given a freed number starts clean; its `/workspace/<bot>` folder stays. A bot's commands start in that folder through `sh -c 'mkdir -p "$1"; cd "$1"; exec sh -c "$2"'`, made again if it is gone, and run_shell's through the computer-server's working folder. open_browser asks the bridge of its own screen whether Camoufox is open (`camoufox-browser --is-open`), since another bot's Camoufox is a process on the same computer. Rejected: the map inside the computer (botdot's data holds the truth; the helper has none), a number derived from the bot id (two bots could meet), one supervisord with a program per bot (its file is fixed, and a bot's screen would start with the computer), and keeping the profile by screen number (the next bot would get the deleted one's logins).
