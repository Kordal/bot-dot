2026-11-03: A PDF in the document viewer is shown by the platform's own renderer, not pdf.js: the web page (and the desktop app's WebView2 and WKWebView) frames its raw address, which already comes `inline` and unsandboxed, so the browser streams it and a 5 MB scan doesn't hold up the page; a browser without a PDF viewer (`navigator.pdfViewerEnabled === false`, a phone's) keeps Download, which opens it in a tab. Android draws it with `PdfRenderer` from the cached copy Share already makes, a page at a time as it scrolls into view, at the screen's width, two fingers to zoom. The server marks nothing new: the apps go by the view's `type`, so its `kind` stays `none` and an older Android app keeps Save and Open. Rejected: pdf.js (about 1 MB of script to ship and keep up to date for what every desktop browser already does), a new `kind: "pdf"` (an older app would draw it as empty text), and Open in another app as the only way on Android (it leaves botdot for a file the owner only wants to glance at).
