2026-10-20: The owner adds an SSH key in the Vault (`POST /api/vault/ssh-keys`), pasted, picked or generated, and it is saved as Bitwarden's own SSH key item, so `run_with_ssh_key` uses it unchanged. Its public key and fingerprint are read from the key with Node's crypto (`lib/ssh-keys.js`), not with `ssh-keygen`, which the image does not have; `bw create item` needs all three. Only OpenSSH's format without a passphrase is taken (a bot can't type one, and Bitwarden already encrypts the key), and a generated key is ed25519 with no choice of type. Rejected: storing keys in the built-in vault (every SSH key is Bitwarden's since #44), and RSA or PEM keys, which `ssh-keygen -p -f KEY` converts. ([#160](https://github.com/Kordal/bot-dot/issues/160))
