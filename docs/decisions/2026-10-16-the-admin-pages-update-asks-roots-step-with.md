2026-10-16: The admin page's Update asks root's step with the same request folder as an account, by an empty file named `UPDATE`, which no account can be named (`[a-z][a-z0-9-]{1,23}`) and which, unlike a hidden `.update`, wakes systemd's `DirectoryNotEmpty` (it skips hidden files), and root's step takes it before the accounts' requests. Root's step says back what it did in a folder of its own, `front-door/status` (`version.json`, `update.json`), which only root writes and the front door mounts read-only; the front door never runs the update or reads the installer's output, which stays in `update.log`, root's alone. (Since [ADR 045](../adr/045-the-update-runs-in-phases-of-its-own-apart-from-the-install.md) root's step writes the last 40 cleaned lines of a failed update's log into `update.json`.)
