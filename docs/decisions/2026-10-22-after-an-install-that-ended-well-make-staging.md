2026-10-22: after an install that ended well, `make staging` keeps `latest` and one `previous` image of `bot-dot/server` and `bot-dot/desktop` in the machine's Docker and removes their other images and the nameless ones `make images` built (label `dev.botdot.self-built`), never forced; one previous is enough for a manual rollback. Before the build the running image gets the tag `before-deploy`, as Docker's containerd image store drops an image whose tag a build takes; it becomes `previous` only after the install ended well, so a failed deploy never moves `previous`. It is not carried into the accounts' Docker: a rollback retags it on the machine and reruns `install.sh`, which hands it over again. The build cache is trimmed with `docker builder prune --all --keep-storage` to `STAGING_CACHE_GB` (default 15 GB, about one full build, so the next build stays fast); that cache is the machine's, not only botdot's, and no `docker system prune` or image prune runs.
