2026-10-18: A bot may use a saved login in a command on its own computer (`run_with_login`, the values in `BOTDOT_USERNAME` and `BOTDOT_PASSWORD`) only for a login the owner marked "Usable in its computer" (`inComputer`), off by default and set per login, because the bot controls its computer and the command, so a bot that tries can get the value (echo it encoded, or run a fake server); blanking the secret out of the output (as it is, URL-encoded, base64, and base64 of `username:password`) only stops accidental leaks into the chat and logs. It is meant for secrets that only guard something inside that computer, such as the local Proton Bridge password, not account passwords. The values reach `docker exec` through the docker CLI's own environment (`-e NAME` without a value), never its command line or a file. Rejected: a switch per bot (it would hand every login shared with that bot to its commands), and keeping secrets to the browser and `api_request` only (the owner's Mail Triage bot could not sign in to Proton Bridge's IMAP).
