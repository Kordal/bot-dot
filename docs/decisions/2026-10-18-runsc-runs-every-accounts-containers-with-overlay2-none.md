2026-10-18: runsc runs every account's containers with `--overlay2=none`, so what a bot's computer writes (its home, `~/.ssh`, its Tailscale login, what it installed) goes to its own layer on the account's disk and outlives a stop. runsc's default, `--overlay2=root:self`, keeps those writes in the sandbox's own overlay and drops them when the container stops: tried on runsc release-20261012.0, a file written in a container was gone after `docker stop` and `docker start`, and kept with `none`. A container made before keeps what it writes from its first start under the new flag; what it wrote before is lost already. Writes go through gVisor's gofer to the host, which may be slower than the sandbox's own overlay (not measured). botdot starts Tailscale again, as the bot, when a computer whose saved state holds a login starts (`botdot-tailscale resume`), with no `tailscale up`, so it never asks for a new approval and keeps a `down` the bot chose. Rejected: a named volume per computer for `/home/bot` (`none` is enough, and the volume would keep only the home, not what root installs or the browser's profile outside it).
