2026-10-09: A bot's computer kept on for the owner's step (`keep_computer_on`) is held in its own file, `computer-holds.json` in botdot's data folder, one record per bot with when the hold started (`lib/computer-holds.js`), so that it survives a restart of botdot: every minute and at start-up botdot turns a held computer on again if it is off, and ends a hold 1 hour after it started, from that saved start. The hold starts when the run that called the tool ends, however it ended (a Stop or the time limit too, since the bot asked for the step before). The owner's message ends it when its run starts, a message in the bot's own chat only (`ownChatMessage`): a turn in a group, a carried-on run, a job, another bot and the Chief leave it, as a run that carries on after the owner's OK is no message. "Turn off", "Reset", deleting the bot and a change of its computer setting end it too. A bot whose computer stays on all the time holds nothing. Rejected: keeping it in `bots.json` (a bot's settings, which only the owner and the Chief change); a Docker restart policy (always-on computers use none either, and it would not end after the hour); a timer per hold (it is gone after a restart, and the minute's look is there already for always-on computers).
