2026-10-20: A steered message reaches a bot's run through a `PostToolUse` hook in a `--settings` file botdot writes for the run (`lib/steer-hook.js`), not through `--input-format stream-json` with stdin kept open. Spiked on Claude Code 2.1.304: a message written to an open stdin can't be taken back, can be echoed (`--replay-user-messages`) and still never read when it lands while the last answer is made, and one written after the turn's `result` starts a second turn by itself. With the hook the server takes the message in the moment the run reads it, so Take back works until then and a message is read once or starts as its own run. The hook's text reaches Claude as hook context, not as a user turn. ([#173](https://github.com/Kordal/bot-dot/issues/173))
