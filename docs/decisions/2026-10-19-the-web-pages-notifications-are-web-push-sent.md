2026-10-19: The web page's notifications are Web Push sent by the botdot server itself (`lib/web-push.js`, `lib/push.js`): VAPID (RFC 8292) with ES256 and the payload in `aes128gcm` (RFC 8291), with Node's `crypto` and no package, so an iPhone gets them from botdot on its Home Screen with no relay and no Apple developer account. The server follows its own feed and decides what to send by the Android app's rules (`new`, `notify`, once per card, not while the web page is in use), since a browser keeps no feed open; what rang is kept in `push.json` so a restart rings nothing again. The payload is `title`, `body`, `target` and `tag`: the tag lets a newer push of the same chat or card replace the older one. The service worker caches nothing. Rejected: the `web-push` npm package (a dependency for about 100 lines), a relay or Apple's APNs (an account and a server outside the owner's), and the page making notifications from the feed (nothing would arrive with the page closed). ([#87](https://github.com/Kordal/bot-dot/issues/87))
