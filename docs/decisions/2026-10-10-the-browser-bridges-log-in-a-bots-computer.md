2026-10-10: The browser bridge's log in a bot's computer (`/home/browser/bridge.log`) is bounded by the launcher (`bound_log` in `deploy/desktop/camoufox-browser`), not by the shell line that starts it, because only the launcher sees Camoufox's output over a long run and it is copied into every computer on each start. Once it is the bridge (after the already-running check, so a second start touches neither file) it moves the previous run to `bridge.log.1`, trimmed to its last 1 MiB, and points its own stdout and stderr, which Camoufox's processes inherit, at a pipe it copies into a fresh `bridge.log`; when that would pass 1 MiB it keeps the last half from a line start, so the newest lines stay at the end and at most about 2 MiB are kept. A log that cannot be moved, opened or written leaves the bridge running with less logging, and the pipe is read on, so a writer never blocks. Camoufox is imported when a page is first asked for, not as the launcher loads, so a broken Camoufox is told in that log (the shell's `>>` that caught it before is gone), and at exit the launcher waits up to 2 seconds for the copy, so a crashing bridge's traceback reaches the log. Rejected: a Python `logging` handler (Camoufox's processes write to the file descriptors, not through it); truncating on start only (an always-on computer runs one bridge for weeks); rotating inside a run to `bridge.log.1` (it would drop the previous run). ([#355](https://github.com/Kordal/bot-dot/issues/355))
