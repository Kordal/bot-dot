2026-11-02: Claude Code goes from 2.1.309 to 2.1.316, and a bot that has to wait uses Monitor or Bash's `run_in_background`, the two ways 2.1.310+ offers when it refuses a long `sleep` ([#641](https://github.com/Kordal/bot-dot/issues/641)). Checked with real `-p` runs on 2.1.316 with a bot's flags: Monitor is the only new tool, and its commands are checked against the run's Bash rules (`Bash(touch *)` lets Monitor run `touch` and nothing else), so no bot is given a Monitor rule. A bare `Monitor` rule runs any command even with no Bash rule, and `Monitor(…)` does nothing, so a Monitor rule in a bot's settings is dropped from its run, and a run without Bash, and the Chief, have Monitor in `--disallowedTools`. Work left running keeps Claude Code going after a result and a second turn writes the real reply, so a bot's run that started such work ends at its process exit, not at its first result (the 0.5 s of #205 is kept for every other run). Keeping nonessential traffic on instead was rejected: it gives back #205's start and exit gain and the block may not stay tied to it.
