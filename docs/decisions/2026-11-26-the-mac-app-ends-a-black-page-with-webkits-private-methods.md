2026-11-26: the Mac app notices WebKit replacing the window's GPU process (`-[WKWebView _gpuProcessIdentifier]`, compared every 2 seconds while the window is in view and when it comes back) and, on a botdot's page, ends the page's web content process (`_killWebContentProcessAndResetState`) and loads the address again, because the page's process reconnects to the new GPU process and never draws again, there is no public callback for a lost GPU process, and only a new web content process draws (found in the macOS log and by ending the process by hand); every private method is called behind `respondsToSelector:`, so a macOS without one does nothing. Rejected: `_killWebContentProcess` (a no-op on the macOS tried: the process lives on, checked with a small WKWebView harness), resizing or reloading the window (a reload keeps the process, which stays black), an official-API-only fix (WKWebView has no GPU process callback) and Tauri's default reload after a terminated process (it is a plain `reload()`, which has nothing to load where WebKit has dropped the page's address, as it does after `_killWebContentProcessAndResetState`; the app sets its own handler with `on_web_content_process_terminate`, which loads the address it kept).
