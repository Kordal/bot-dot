2026-10-19: An account's share is CPUs, RAM and disk; "computers at once" is gone, since the account has one computer (ADR 035), and a share the front door or root's step kept with `computers` is read without it. Root's step writes the share's RAM and CPUs into the file the docker-helper already reads (`share/share.json`, `{"cpu":…,"ram":…}`), and the helper gives them to the account's computer as `--memory`/`--memory-swap` (equal, so no swap beyond it) and `--cpus` when it makes it, or with `docker update` before it starts a stopped one, because gVisor takes no `docker update` of a running computer: a changed share sizes it from its next start. A Docker that refuses them (a rootless one without cgroup controllers) gets the computer made without them, with a warning in the helper's log, since the share on the account's unit still holds; whether gVisor (`--ignore-cgroups`) enforces them is only seen on a real machine. `BOT_DOT_COMPUTER_MEMORY`, when set, is its memory instead. The admin page's use says whether that one computer is on. Rejected: restarting the computer when the share changes (it is always on, and holds every bot's work).
