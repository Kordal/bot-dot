Three checks only: no line on what the bot never does (any of "never", "not", "n't", "nigdy", "nie" passes: a miss that is rare beats a false alarm); the wake line (or, without one, the whole task) names a schedule ("every morning", "daily", "at 8:00", "codziennie") and the bot has no job, said as "no job yet; add it with add_job" so it is no noise when add_job comes next; an icon or hat the call set that another bot already has (a drawn hat is never compared). A task the user dictated word for word is told apart by the Chief passing `verbatim: true` (words alone cannot show it): that drops the "never" hint, and the job hint stays, since a schedule with no job is a gap in the bot, not in the words. `update_bot` checks only a prompt or outfit it changed, on the text as sent (it may wait for the owner's OK). Hints advise: the bot is saved as sent. Rejected: checking in `POST /bots` (the HTTP answer would change for apps that never read it, and the owner's own bots would get hints they cannot act on); a model reading the task (cost and a new failure for a check that must be cheap and certain); refusing the save (a dictated task must be saved as given).
