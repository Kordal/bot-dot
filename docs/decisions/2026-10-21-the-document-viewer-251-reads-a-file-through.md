2026-10-21: The document viewer (#251) reads a file through one JSON answer of the routes that already download it (`?view=1`, capped at 1 MB and 1,000 lines), not a second store or a converter: a PDF and Office files get no preview and keep Download. A path a bot names is read with `GET /api/bots/:id/path`: a relative path in its workspace on the server (resolved with `realpath`, which must stay in the workspace), and `~/`, `/home/box/` or `/workspace/` on its computer through the existing `runShell` (`docker exec` as `box`, through the docker helper's list), running one fixed script: the path single-quoted, `realpath -e` inside the computer so a link that leads out of those folders is refused there, `-f` and `-r` checks, the first 1 MB as base64. A computer that is off answers `409` and is never started by a read; the owner starts it. Rejected: reading the computer's volume from the server (the paths and links are the container's, and its files belong to `box`), starting the computer to read a file, and `docker cp` (a new helper command for one read). A path is linked in plain text and in an inline `code` span that is exactly one path, never in a code block, from a fixed list of extensions, so `Node.js` stays a word; the web and Android share the cases in `test/fixtures/file-paths.json`. On the web "Open in full window" lets the viewer take the whole chat row instead of opening a page. The Chief can't read paths: it has no workspace or computer of its own, and a bot's files stay the owner's. Left out, as the issue's mockup is only a design: a list of the replies that name a file and an "Ask about it" button. ([#251](https://github.com/Kordal/bot-dot/issues/251))
