2026-11-04: A public install shows the exact DNS record its domain needs (A, and AAAA when the machine has IPv6) and what the domain resolves to now, before the long downloads and again when Caddy doesn't answer. The machine's public address comes from Cloudflare's trace at `1.1.1.1` and `[2606:4700:4700::1111]` (addresses, so no DNS, 5 seconds each); the domain's from `getent`. An address in Cloudflare's ranges is its proxy, which must be DNS only for Caddy to get the certificate. When the DNS is right but Caddy has no certificate, the installer restarts Caddy once, since it waits longer after each failed try. Skipped with `BOT_DOT_TLS=internal`. Rejected: a third-party "what is my IP" service (another party sees every install), and reading the address off the network interface (wrong behind NAT and on clouds that map it, such as EC2).
