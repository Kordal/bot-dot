2026-10-19: The account's computer keeps `/home/box`, `/workspace`, `/home/browser` and `/var/lib/botdot-tailscale` (#106) on four named volumes (`<computer>-home`, `-workspace`, `-browser`, `-tailscale`), so an update to a newer desktop keeps the files, the browsers' logins and the computer's Tailscale login, and loses only what apt installed. This takes back the rejection of a volume for the home in #68: `--overlay2=none` still keeps everything across a stop, but not across a new container. An update copies a computer made before the volumes onto them first (`docker cp` streamed into a throwaway container of the desktop image that mounts each volume at its own place, so the folder keeps its owner), and changes nothing if that fails; the Tailscale folder, which the desktop does not have, is skipped when the computer never made it. A bot's old computer's home is copied into `/workspace/<bot>/old-computer`, not into `/workspace/<bot>` itself, so its dotfiles and folders never overwrite what the bot keeps there now. The Chief's request for a reset is a card of kind `chief-action` with words of its own (title, `meta`, `text`), which both apps already draw, instead of a new kind of ask. A reset or an update is refused while a bot with a computer is in a run. ([#107](https://github.com/Kordal/bot-dot/issues/107))
