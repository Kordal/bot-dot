Which files are kept in mind is stored in botdot's own `data/file-pins.json`, not in the bot's folder, which the bot can write. A pinned file's text comes whole while the 8,000 characters for all pinned files last; a longer file, or one with no text (a PDF, an image), comes as the summary the bot writes of it once with `pin_file` and that is kept with the pin, not as a memory note as the issue suggested: it goes when the file is deleted and stays out of the memory other runs search. Until it has one, every run is told to read the file and write it. At most five files are kept in mind. The Files section in the bot's settings is a control the Chief could stand in for, against AGENTS.md rule 5, on purpose: the issue asks for it, and opening a file is the owner's alone. The Chief lists and deletes a bot's files by name, never their content or summary, and can't pin them (the owner or the bot does). Left out: pinning from a file chip in the chat.
