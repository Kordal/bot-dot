2026-10-16: The front door, which never runs as root, gets a new account made through a request folder and root's one step, not a socket or sudo: it writes an empty file named as the account in `front-door/requests` (owned by root, writable by the `botdot-door` group alone), and systemd's `botdot-accounts.path` (`DirectoryNotEmpty=`) starts the oneshot `botdot-accounts.service` as root, which runs `install.sh --requested` from a copy only root can change (`/var/lib/botdot/bin/install.sh`, `0600` in a `0700` folder). That step takes no argument from the front door, reads the file names, makes only names that are an account's name (checked with `case`, one line) and that the front door's own data has as an account, makes them with the same `account` function the install uses, each in a subshell that stops at its first failure, and installs, asks and starts nothing else; it removes each request when done, made or not (a folder too, so that one stuck request can't stop the next), and logs to the journal. An account that wasn't made stays "isn't running" for its owner, and why is in `journalctl -u botdot-accounts`; a retry is left for later. Without systemd (a container, as in `make install-real` and `make accounts-real`) the installer starts a loop that looks every 3 seconds and says it won't come back after a restart. Rejected: a root daemon on a socket (a long-running root listener, and parsing its input), sudo rules for the front door's user (a root command line built from what the front door sends), and a setuid helper (none in botdot, and the front door runs with `no-new-privileges`). ([#467](https://github.com/Kordal/bot-dot/issues/467))
