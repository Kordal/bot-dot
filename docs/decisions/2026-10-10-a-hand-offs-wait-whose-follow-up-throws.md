2026-10-10: A hand-off's wait whose follow-up throws as it is started or queued (`queue.json` could not be written, the run could not start) stays in `awaits.json`, as with a full queue, and is tried again after each run's end, each answer and every 30 seconds, with no limit; each failure is logged and the bot's face keeps showing that it waits, because settling it lost the hand-off for good. A retry can't start a second follow-up: a queued one is found again by its key (`replies:<runId>`); a later answer that can't be saved with a follow-up already queued is taken along in memory and its wait settled, as before (kept, it would start a second follow-up once the first had started); and once `startRun` has recorded the run nothing after it throws for a follow-up. The bot's inbox, which holds the answers, is only read until the run is on record and emptied after, so a start that throws leaves them for the retry; an inbox that can't be emptied then is logged and read once more by the next run. Rejected: settling it anyway (the hand-off never came back); a limit on attempts with a note to the bot (nothing asked for one, and a full queue has none).
