2026-11-22: the Fixed notice (#1569) is two fields on the report in `GET /front-door/feedback`, not a separate list: `fixed` (the account's server ships the note named by `fixedIn`, worked out on each request from its `GET /api/version`, so it needs no timer and no stored state that could go stale when the account switches) and `fixedSeen` (kept with the report by `POST /front-door/feedback/<id>/fixed-seen`, so every app of the account stops showing the notice), and `fixed` stays `true` after the notice is closed so My reports and the notice read one answer. Rejected: a stored `fixed` set when the status arrives (it would say "fixed" before the account runs the fix), and a seen mark kept in each app (the owner would see the notice again in the other app).
