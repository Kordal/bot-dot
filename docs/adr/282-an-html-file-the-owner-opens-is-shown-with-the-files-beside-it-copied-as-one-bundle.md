# ADR-282: An HTML file the owner opens is shown with the files beside it, copied as one bundle

- **Status:** Proposed (the owner accepts it on merge)
- **Owning task:** [#1762](https://github.com/ladrok/bot-dot/issues/1762)
- **Builds on:** [ADR 281](281-an-html-file-the-owner-opens-is-shown-rendered-on-the-sandbox-address-from-a-copy-of-its-bytes.md) (the preview, its store and its address), [ADR 072](072-an-interactive-page-is-a-bots-static-site-sandboxed-on-an-address-of-its-own.md) (the sandbox's address and its rules, the checks of a bundle, a tar made by the box user)
- **Amends:** ADR 281's "Scope is the one file": the preview is now the file's folder, when that folder can be copied; the one file stays as the fallback

## Context

ADR 281 shows an `.html` file the owner opens rendered on the sandbox's address, from a copy of the bytes the viewer read. The copy is that one file: what the page loads by a relative path (`style.css`, `app.js`, `img/logo.png`) is `404`. A mockup that links a stylesheet beside it looks plain, and a bot's small site is almost always more than one file.

The rule ADR 072 set and ADR 281 kept stands: the sandbox never reads a bot's workspace, the account's computer or a project's folder. It reads only botdot's own data folder, which no bot writes to. So the neighbours cannot be served where they lie; they must be copied there first, by botdot, at the owner's tap.

## Proposed decision

- **The folder is copied, as one bundle.** When the owner opens an `.html` or `.htm` file (the viewer's `?view=1` answer, from a bot's workspace, the account's computer or a project's folder), botdot reads the file's own directory and its subfolders, and copies the files a page may hold into `previews/` in its data folder as one **bundle**: `previews/<hash>/<path…>`, the way a published page's version is kept (`sites/…`, ADR 072). Which files and how many are ADR 072's checks, kept as they are: its list of allowed file types (`html css js json png svg woff2 …`), plain names (letters, digits and `. _ - @ +`, no dot files, at most 8 folders deep), at most 300 files and 5 MB, and no links or special files. What the checks leave out (a `.mp4`, a `.env`, a file with a space in its name) is simply not in the bundle.
- **One hash names it.** `<hash>` is the SHA-256 of the sorted manifest of each kept file's path and its own SHA-256. The same files make the same bundle, whatever the order they were read in and whichever file of the folder was opened, so opening one folder's pages again, or two of its pages, keeps one copy. A changed file is another bundle: an address already open keeps showing what its opening read, as ADR 281's did.
- **The token names the bundle and the entry.** A bundle's address is `<origin>/<account>/<token>/<file>`, the token signed like a page's and a single copy's, in its own shape: `{ k: "b", h: <bundle hash>, n: <entry's name>, e: <expiry> }`. The entry is the file the owner opened, a plain name at the bundle's top. The sandbox answers a request for a path *inside that bundle* and nothing else: a path that is not a plain name of an allowed kind (`..`, an absolute path, a name with a backslash or NUL), a file not in the bundle, a link, and a hash's name as a path are `404`; a wrong or run-out token is `403` before any file is looked for. A bundle's token opens no page, no single copy and no other bundle, and none of theirs opens it (`k: "p"` and a page's `b`, `s`, `v` are other shapes).
- **The entry is the bytes the viewer read.** The bundle holds the entry as read for the Source view, not a second read of the folder, so Rendered and Source never differ. `index.html` and the folder's own address are the entry when the entry is `index.html`, or when the folder has no `index.html` of its own (the entry then answers for both, so its frame ends in `index.html`, the name every app already takes); when the folder has another `index.html`, the frame ends in the entry's own name and `index.html` is that other page, so a link to it goes there.
- **How the folder is read, per place.** On this server (a bot's workspace, a project's folder) botdot walks the directory itself, through the same filesystem layer the viewer uses (`principal-fs`, whose calls are made one at a time, so the walk gives the event loop back between folders and files and asks for a size per file and the bytes of a kept one only): every regular file is counted, a link or special file anywhere refuses the folder, only the files that may be kept are read, and a name swapped for a link between the listing and the read is not followed. On the account's computer, which the viewer reads as box with a fixed script, botdot reuses how `publish_interactive_page` gets a folder: a fixed script readies the folder (it follows links itself and answers the folder's real path only if it is inside `/home/box` or `/workspace`, and only if it holds at most 300 files and 5 MB together), and `packFolder` then makes a ustar tar as the box user, read by `untar`, in which a link refuses the whole folder. The folder is therefore small before it is packed, on the account's computer and on an External Virtual PC alike.
- **The fallback is today's behaviour.** A folder over the limits (more than 300 files of any kind, or 5 MB of them), with a link or special file in it, that can't be read (the computer is busy or answers badly, the folder is not under the allowed places), whose entry's name is not a plain one (`my page.html`), that holds no more than the file itself, or that can't be kept on disk, is the single-file preview of ADR 281: the same frame, the same `index.html`, the same note. `uploads/` of a bot's workspace, where files given to it pile up, is never taken for a site's folder. The answer never fails for it: the owner always gets what they got before.
- **A file whose directory is a big root is the fallback.** The folder is the file's own directory, not a project: an `.html` file at the top of a bot's workspace, or of a project's folder, sits beside everything that bot or project has, counts every file (`.git` and `node_modules` included), and so passes 300 files or 5 MB and is shown as the one file. A mockup in a folder of its own is what the bundle is for; no setting or path picks another folder.
- **Limits and sweep.** ADR 281's rules, for bundles: a bundle lasts as long as an address does (12 hours from the last time it was put), at most twenty are kept beside the hundred single copies (the oldest go first; a bundle is up to 5 MB), the sweep runs on each put and at start and removes whatever is not a copy (a name that is no hash, a folder where a file belongs, a link, a half-written temporary folder), and a backup leaves `previews/` out. A bundle is written beside its place and renamed into it whole.
- **The answer and the apps.** `preview` becomes `{ frame, expires, bundle? }`: `bundle: true` says the folder came with the file. `frame` is still an address on the sandbox, ending in `index.html` or, beside another `index.html`, in the entry's plain name; apps accept both and frame nothing else. `features` has `html-preview-bundle` (frames may end in another name; `bundle` exists). An app that does not know it draws the frame as before, with the old note, and an old app shows the source of a file whose frame ends in another name. The note beside the toggle says "The files beside it load, nothing from the internet" for a bundle and keeps "Only what is in this file loads" for the one file. The web page and Android change nothing else: Android's WebView already keeps a page to its token's prefix, which holds the neighbours. The iOS app gets this with the viewer ([#1355](https://github.com/ladrok/bot-dot/issues/1355)).
- **The CSP and the sandbox are exactly ADR 281's and ADR 072's.** The front door's listener is unchanged; every answer carries `sandbox allow-scripts` and a CSP that lets the page load only its own token's files (`script-src`, `style-src`, `img-src`, `font-src` and `connect-src` limited to that prefix). Nothing loads from the internet: that is out of scope here and the CSP does not move.

## Alternatives

- **Publish the folder as an interactive page**: ADR 281 turned it down for one file and it holds for a folder. The bot would have to publish it, the owner would see a new page in Pages for every file named in a reply, and a file the owner or a teammate wrote is not a bot's to publish.
- **Let the sandbox read the folder in place** (a token naming a bot, a project or the computer, and a path): the token would carry a place, and the sandbox would become a reader of the bot's workspace, of the computer and of a project's folder, a larger door than ADR 072's, which reads only botdot's own folder. A script on the page could then reach any file the sandbox can read by a guessed path. The copy costs at most 5 MB for hours, at most twenty times.
- **A fixed set of files** (the file's `<link>`, `<script>` and `<img>` read out of its source and only those copied): botdot would parse a bot's HTML, and a stylesheet's `url()`, a script's `fetch()` and an `import` would each need another reader. The folder's allowed files under ADR 072's checks are the same set of files a published page may hold, with no parsing.
- **A bigger or configurable folder** (the parent folder, or the project's folder): the limits are what keep the copy small and the disk bounded; a root with hundreds of files is exactly what must not be copied on a tap.
- **The bundle as a zip or a tar kept as one file**: one file to sweep, but every request would have to read the archive. A folder of files is served as ADR 072's versions are, with the existing serve code.

## Consequences

- A mockup with a stylesheet, a script and pictures beside it shows as it is, from the first tap, with no publishing. The page still runs in the closed box ADR 072 built and cannot reach the account.
- Opening an HTML file now reads its folder: a walk of at most 300 files on this server, and on the computer one small script and one `packFolder`. It happens once per opening, and only for an HTML file that would be shown rendered anyway; a slow or failing computer leaves the one file.
- A page's script can read the other allowed files of its bundle (`fetch('data.json')`), which are files of the same folder the bot wrote the page in and could read itself. The residual risk of ADR 072 stands (the CSP does not cover WebRTC): files in the bundle could in principle leave through it. This is the reason the bundle is kept to the file's own folder, to ADR 072's file kinds (no `.env`, no dot file, no archive, no database) and to the limits, and does not reach a parent folder or a project.
- Disk: at most twenty bundles of at most 5 MB, each gone after 12 hours without being opened, and the hundred single copies of at most 1 MB as before.
- A folder with a dot folder such as `.git`, or with `node_modules`, passes the limits and is the single file. That is the price of counting every file before copying any.
- Case: a bundle's names are served as written, and the store follows its file system's rules on case, which on the servers botdot runs on (Linux) is exact.
