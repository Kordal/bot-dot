# ADR-280: A language is a folder of lib/i18n, and the registry lists every one

- **Status:** Accepted
- **Extends:** [ADR 108](108-the-interface-speaks-english-or-polish-from-one-dictionary-the-server-hands-out.md), whose one dictionary per language and English keys stay as they are; its "English or Polish" becomes any language of the registry.

## Context

The interface speaks English or Polish (ADR 108). Twelve more are to come, each in a pull request of its own, written at the same time by different agents: German, French, Spanish, Dutch, Brazilian Portuguese, Simplified Chinese, Japanese, Italian, Russian, Korean, Turkish and Indonesian. "English and Polish" was written into the code in many places: the list of languages (server, web page, Android, What's new), the plural rules (Polish's one/few/many by hand on the server and the phones), the dates, a bot's browser locale, the word for the language a bot is told to write in, the Play listing's captions, and the words botdot reads in what people write (a "no" that corrects a bot, "because" before a decision's reason, the endings Polish puts on a bot's name, a source that says "brak"). Twelve pull requests each adding its code to those lists would conflict on every one of them, and each would have to know them all.

## Decision

- **One registry, all languages up front:** `lib/i18n/languages.json` lists each language once: `code`, its own `name`, its `english` name, the `browser` locale (lib/browser-locale.js), the `date` locale (the server's and the web page's Intl), the phones' date patterns `longDay` and `shortDay`, and `spaced: false` for a language written without spaces between words. It already holds the fourteen, so a language's pull request never touches it.
- **A language is offered when its folder exists:** `lib/i18n/<code>/`. Offered means: in the Settings picker, accepted as the account's `language` (`PUT /api/settings`), served by `GET /api/i18n/<code>`, used by What's new, by the server's sentences and by the prompts. English is always offered and has no folder: its words are the keys and the code's own. `test/i18n.test.js` fails on a folder that is no language of the registry, on a file in a folder that is not one of its kinds, and on any string an offered language lacks: a folder is complete or it is not there.
- **The codes** are BCP 47 tags as the code needs them: the base language alone where one form is meant (`de`, `fr`, `es`, `nl`, `ja`, `it`, `ru`, `ko`, `tr`, `id`), `pt-BR` because Brazilian and European Portuguese differ in words and in plural rules (CLDR gives `pt` and `pt-PT` different "one"), and `zh-Hans` because the script, not a country, decides the written form (Intl, Android's `Locale.forLanguageTag` and Foundation all read it; a bot's browser gets `zh-CN`). The folder's name, the setting's value and the What's new folder are that code.
- **The server hands out the list** (ADR 003): `GET /api/i18n/<code>` answers `languages` (the offered ones: `code`, `name`, `locale`, `date`, `longDay`, `shortDay`) and `phrases` beside `strings`, English's too, and `GET /api/settings` answers `languages`. The web page and the phones draw the picker from it and keep it with the dictionary; no app has a list of its own. Feature `languages` says so; an app on a server without it keeps its old English and Polish.
- **Plurals by CLDR's categories.** A plural's value is an object keyed by the language's categories (`one`, `few`, `many`, `other`…): Polish's one/few/many stay as they are. The server and the web page pick with `Intl.PluralRules`. Kotlin has none, so `I18n.form` in the shared data layer (Android and iOS) has a small table of CLDR's rules for whole numbers in the fourteen languages, which `PluralRulesTest` holds to `test/fixtures/plural-rules.json`, written from Intl (`node lib/i18n/keys.js plural-fixture`, checked by `test/i18n.test.js`). A form a dictionary lacks is `other`, then `few` (a Polish or Russian fraction takes the few form's words), then `many`. The test asks each plural for exactly the categories the language's whole numbers take (Spanish, French, Italian and Portuguese have a "many" for millions).
- **The words botdot reads** in what people write are English's in the code that reads them, and every other language's in its folder's `phrases.json`, one list per kind (`stopWords`, `corrections`, `never`, `schedule`, `yes`, `no`, `nothingNew`, `because`, `noSource`, `nameEndings`, `password`; `lib/i18n/phrases.js` says what reads each). The lists of every offered language are read together, as English and Polish were: an owner may write in a language other than the interface's. The apps get the kinds they read (`because`, `noSource`, `nameEndings`, `password`) with the dictionary. Polish's words moved there from the code. The lists of many languages that were already in the code (the yes and no of answer buttons, a report that says nothing new) stay, and a folder's words add to them.
- **A job's schedule in words** is grammar, not a list: a language's is its folder's `cron-words.js`, an object of the shape of English's in `lib/cron-words.js` (Polish's moved there). Without one a schedule is said in English.
- **Bots and the Chief write in the account's language**: the name they are told is the registry's `english` (`languageNote`, `languageName`), for every offered language.
- **What's new**: a note's twin is `whats-new/<code>/<id>.md` for any offered language, and a note without one comes in English. Every note still has its Polish twin, as `test/whats-new.test.js` checks; another language's twin, when there is one, is checked like it.
- **The Play listing** is per-language data: `docs/google-play/listing-<code>.md` and `docs/google-play/captions/<code>.json` (the feature graphic's line and each screenshot's caption). `caption.cjs` and `graphics/make.cjs` draw every language with captions, and the Play screenshots workflow does it after it takes the pictures, with Noto CJK.
- **Context for translators**: `node lib/i18n/keys.js missing <code> [area] --where --limit N --offset N` prints each string a language lacks with every place the code draws it (file:line and the lines around it), in chunks. `lib/i18n/GLOSSARY.md` says what each of botdot's words is; each language writes its own `GLOSSARY.md` from it (Polish's table moved to `lib/i18n/pl/GLOSSARY.md`). `lib/i18n/README.md` has the checklist.
- **Chinese, Japanese and Korean letters**, which Geist has not, come from the system's fonts. The web page names each language's own (`:root:lang(ja)` and the like; `i18n.js` sets the page's `lang`), and the Android app sets the interface language's locale on its text styles, so the shared Han characters take that language's forms whatever the phone's language is.

## Alternatives

- **Each language PR adds itself to a list** (the registry with only the offered ones, `LANGUAGES` arrays as before). Twelve PRs would conflict on the same lines, and one forgotten list would leave a language half there. Rejected for the folder test.
- **The plural rules as data from the server** (CLDR's rule strings, read by a small parser on the phones). One source for every app, but a rule parser in Kotlin is more code to trust than fourteen short rules held to Intl by a fixture. Rejected; the registry is fixed, so the table is too.
- **English's words in `lib/i18n/en/phrases.json` too.** Uniform, but English would need a folder that is no dictionary, and the code would read English through a file it is written in anyway. Rejected: English is the code's language, as for the dictionary's keys.
- **Only the interface language's phrases (with English).** Fewer false matches across languages, but the server reads many of them where no account language is at hand, and an owner who writes Polish on an English screen would lose what botdot read before. Rejected; each list is kept specific instead (the README says so).
- **Android string resources per language** (`values-de/`). Rejected for the same reasons as in ADR 108.

## Consequences

- Adding a language is adding `lib/i18n/<code>/` (its dictionary, glossary, phrases and, if it likes, schedule words), its What's new twins, `docs/google-play/listing-<code>.md` and `docs/google-play/captions/<code>.json`: no shared code or list. Once it is merged, every new string and every new What's new note is written in it too (AGENTS.md).
- A language pull request must be complete: a missing string fails `make test`. It must also be rebased before merging, since a string added on `main` meanwhile needs it.
- What is not generalised, and stays as it is:
  - English's "n't" (in `lib/bot-hints.js`) is a pattern in code, not a phrase.
  - A page's file name keeps only Latin letters and digits (`lib/pages.js`, `lib/boat.js` machine names): a title in Cyrillic, Chinese, Japanese or Korean becomes "page" (a second one "page-2"). The title the owner reads is unchanged.
  - A note search (`lib/memory.js`) splits words at spaces and punctuation: a Chinese or Japanese sentence is one word there, so for those languages the note search leans on the meaning search.
  - `because` is matched between spaces: in Chinese and Japanese a decision is split at a dash, or at the word with spaces around it.
  - The desktop app's own few words (its menu, `desktop/src-tauri/src/menu.rs`, and its removal screen) follow the computer's language, English or Polish: they are drawn before any account is known. A follow-up.
  - The Play foreground service video is English: it is made for Play Console's reviewers, not the store.
  - The iOS app's text takes the phone's locale for Han characters until its own screens are in step (ADR 242).
- An older app on a newer server ignores `languages` and `phrases`, and keeps English and Polish and its own Polish words. A newer app on an older server offers English and Polish, and reads only English's words.
