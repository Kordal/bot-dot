# ADR-263: An account may use its own boat.dev key, with one machine for all its bots or one per bot

- **Status:** Accepted (2026-11-23, the owner's decision on [#1617](https://github.com/ladrok/bot-dot/issues/1617))
- **Owning task:** [#1617](https://github.com/ladrok/bot-dot/issues/1617)
- **Amends:** [ADR 088](088-a-bots-computer-may-be-a-machine-of-its-own-on-boat-dev.md) (the External Virtual PC is the admin's key alone; without a key the bots work on this machine), [ADR 096](096-the-accounts-boat-bots-share-one-machine-there.md) (one machine per account, and its one-minute migration of a bot's own machine), [ADR 098](098-the-accounts-computer-is-in-one-place-for-all-its-bots.md) and [ADR 146](146-only-the-admin-moves-an-accounts-computer.md) (the admin moves the account's computer), [ADR 162](162-the-fleet-console-gives-a-managed-machine-its-operators-keys.md) (a managed machine's boat.dev key is the operator's), [ADR 163](163-only-the-admin-chooses-the-size-of-an-accounts-external-virtual-pc.md) (the admin chooses the size), [ADR 261](261-a-bot-may-have-a-place-for-its-computer-of-its-own-under-advanced.md) (a bot's place of its own, which this adds a machine to)
- **Builds on:** [ADR 091](091-a-bots-files-are-copied-when-its-computer-moves.md) (files are copied when a computer moves), [ADR 160](160-the-installer-gives-the-admins-account-its-composio-key.md) and [ADR 206](206-the-machines-composio-key-goes-to-every-account.md) (the machine's key, which an account's own Composio key, kept encrypted with its Vault key in `lib/connectors.js`, wins over), [ADR 254](254-the-fleet-console-moves-one-account-to-another-machine-through-the-off-site-backup.md) (an account moves with its data), [ADR 262](262-a-bots-commands-on-the-external-virtual-pc-go-through-the-accounts-proxy-too.md) (the proxy on boat.dev)

## Context

Until now the External Virtual PC was one boat.dev account's: the admin's key (ADR 088, 162), kept in memory on the machine, and the admin alone decided where an account's computer is (ADR 146) and how big its machine is (ADR 163). Every bot of the account shared its one machine (ADR 096); a machine of a bot's own was removed in #579 (ADR 098). An owner who pays for boat.dev themselves, on a machine whose admin has no key or on a managed one, had no way to use it, and one who wants a bot's browser and files apart from the others had none either.

The owner asks that an account may bring its own boat.dev key, as it may bring its own Composio key (ADR 160, 206), and with it choose where its computer is and its size, and give a bot a machine of its own.

## Decision

- **The key.** In Settings → Computer, with Advanced on, the owner adds, replaces or removes the account's own boat.dev key. It is checked with boat.dev as it is set (`checkKey`: `ok`, `refused`, `billing`, `unreachable`) and kept only when it works; a refusal says why (`400` with the check, `502` when boat.dev can't be reached). It is kept as the Composio key is (`lib/connectors.js`): in `boat-key.json`, mode 600, encrypted with the account's Vault key, which travels in backups. Only its owner may set or remove it: the Chief, a bot and the front door's own header get `403`. The apps are told that one is set, what its check said, how many machines it made and whether the machine has the admin's key (`GET /api/settings/boat-key`), never the key or a part of it, not after it is saved either. It never goes to a computer or to a boat.dev machine: no command, file, header or environment carries it. The check is asked again after ten minutes when the settings open; a key boat.dev refused a call with since says `refused`.
- **It wins.** Both keys are kept in the account's server (`lib/boat.js`): the admin's, set by the front door in memory as before, and the account's own. The account's wins for everything new. `boatReady` and `boat` of `GET /api/version` and `/api/status` are true when either is set; with neither nothing changes (the bots work on this machine, ADR 088). It works on a managed machine (ADR 154, 162) and on a one-account one alike: the account's server holds it, not the front door.
- **A machine is asked about with the key that made it.** A machine made with the own key is marked `own: true` in `boat-machines.json`, and every call about it, and its stop, rest, copy and delete, uses that key; one made before it keeps the admin's. A machine made with the other key than the one in use is let go the next time it is started (stopped with the key it was made with, its disk kept by boat.dev), and a new one is made with the key in use: a machine that is running goes on until it rests (30 minutes). **It is retired, not forgotten.** Its entry moves from `boat-machines.json`'s machines to a list in the same file, `@retired`, by id: `{ box, id, type, name, own?, since }`, where `box` is the account's or the bot's it was, and `own` says which key made it (the account's own, else the machine's). A key in use again, or a restart, does not lose it. Deleting the account (`erase`), removing the own key (`dropOwn`, which counts and deletes the retired ones the own key made, as the live ones) and copying files all use it. The account's files on a machine made with the other key are not on the new one, which starts empty: the owner moves the account's computer with "Copy files" (ADR 091) to keep them, and the copy reads them from the retired machine, started with the key that made it (`moveFiles` with `source`), once for each bot (`copiedBy`: the next copy is from the machine in use, so the older files never replace newer ones twice). It rests after 30 minutes unused, like any machine.
- **Who chooses.** With the own key, the owner moves the account's computer (`PUT /api/settings/computer`, this machine or the External Virtual PC, with "Copy files" or "Start empty" as ADR 091) and chooses the machine's size (`PUT /api/settings/boat-size`); the admin's page and the Chief get `403`. Without it, as before, only the admin does and the owner gets `403`. The two `GET` answers say `ownKey`, so the apps draw the owner's choice or the admin's. The admin's accounts list hides Move and Size for an account that answers `ownKey: true`.
- **Removing the key.** The machines it made, the retired ones too, are asked about first: the owner says "Delete its machines on boat.dev" or "Keep them" (`DELETE /api/settings/boat-key?machines=delete|keep`; `409` with the number when it made some and was not told). Deleting uses the own key; a machine boat.dev refuses to delete because the key is refused is left to the owner at boat.dev, and one it fails to delete (`502`) keeps the key, to be tried again. While a bot's files are being copied it waits (`409`). A bot with a machine of its own goes back to the account's one machine. The account's place is not changed: the bots work on this machine meanwhile, as ADR 088's fallback has them when boat.dev has no key, and each answer says so (`computer-screens`); with the machine's key set they carry on there.
- **Deleting the account** deletes its boat.dev machines with the key that made each (`POST /api/boat/erase`, the front door's alone), the machine's key's and the own key's, the retired ones too. The front door now asks the account on every kind of machine, also one with no key or admin page of its own; it names the account as "not deleted" only where the machine's own key is set and the server gave no answer. On a managed machine, where the owner only asks the console for the deletion (ADR 241), the machines are deleted once the request is in the outbox and the account is suspended, and only then: a request that fails (`503`) or is refused (`409`) deletes nothing. The console's erase of the machine can't do it, because the own key goes with the account's data; so it is the front door, while the account's server still answers, before root's step stops it.
- **Moving an account** (ADR 254, an off-site backup): the key goes with the account's data, since it is in it, and works on the new machine. The console's delete of the old copy keeps the machines the own key made (`{ keepOwn: true }` to the erase), since the new machine uses them; the machine's key's go as before.
- **A machine of a bot's own (`boatOwnMachine`).** Under Advanced, a bot whose computer is the External Virtual PC either shares the account's one machine (ADR 096, the default) or has a machine of its own, as ADR 088 had. The setting is offered only while the account uses its own key (`ownKey`), and for a bot that has one already so it can come back; `400` otherwise. It reuses the `boat-own` kind of `lib/boat.js` and `lib/bots.js`. The machine is named `botdot-<instance>-<account>-<bot's name>-<bot id>` and has the account's size and a 30-minute rest. Switching copies the bot's files when the owner says "Copy files" (ADR 091) and starts empty otherwise; its own machine goes only after a copy from it succeeded, or at once with "Start empty". A browser profile moves only between its own machines, as it did. A bot made new or duplicated shares the account's machine. The apps show both sides as the External Virtual PC. A flag from before #579 is dropped once, when the file is read after this change (`.boat-own-machine` in the data folder marks it done), so an old bot is not given a machine of its own.
- **The migration leaves it.** ADR 096's one-minute migration takes a bot's own machine back to the account's only for a bot that does not want one; one that does is left on it.
- **The Chief.** `update_bot` takes `boatOwnMachine` and `moveFiles`. Going to a machine of its own has costs, so it waits for the owner's card, "Machine on the External Virtual PC: a machine of its own on boat.dev, which has costs" (", with its files" when asked); going back to the account's costs nothing and is applied at once. The Chief never sets the key.
- **The proxy.** The account's proxy goes to a bot's own machine as to the account's (ADR 262): its bridge is handed it as each command starts, and a bot that can't get it does not run the command.
- **No prices or usage limits** in an account's pages or answers (AGENTS.md rule 5): the settings show what boat.dev said of the key and a size's CPUs and memory; "costs" stays the one word for it.
- **Features:** `boat-own-key` and `bot-own-machine`. The web page and the Android app show the settings; the iOS app catches up in [#1375](https://github.com/ladrok/bot-dot/issues/1375).

## Alternatives

- **One key only, the account's replacing the machine's.** Rejected: the admin's key stays the default for accounts that have none, and removing the own key must not leave the account without boat.dev when the admin has one.
- **Send the key to the front door and keep it there.** Rejected: the Composio key is the account's and encrypted with its Vault key, and a front door key store would hold secrets of accounts that the account's backup then lacks.
- **Switch machines at once when a key is added.** Rejected: a running machine would be stopped under a bot's run; the new one is made when the old one rests.
- **Let the admin keep choosing the place and size.** Rejected: the owner pays, so the owner chooses; the admin's page would be changing something that costs the owner.
- **Delete the machines when the key is removed, without asking.** Rejected: the owner may want the files, and boat.dev keeps them under the owner's own account.

## Consequences

- An account that adds a key while on the admin's machine starts new machines, empty: the files on the old one stay on the admin's boat.dev account until the owner copies them with "Copy files" (once for each bot), and until the account is deleted, which deletes the old machine too.
- A key replaced by another boat.dev account's leaves the old key's machines on that account, live or retired: botdot can't delete them any more (a call about one is answered `404`, which counts as deleted, and a new machine is made, or the retired one's copy fails with "gone"). Likewise a retired machine of the admin's key when the admin removes it, or one the owner's key can no longer reach after it was refused.
- A machine whose entry boat.dev refused to delete (not a refused key) stays on the list, retired or not, to be tried again.
- A request to delete a managed account that the console then resumes instead of erasing leaves the account without its boat.dev machines: they were deleted when the owner asked, which is what they asked for.
- When the admin deletes a suspended account whose own key made machines, its server is stopped and they stay on the owner's boat.dev account, which the audit entry says ("its server gave no answer") only where the machine's own key is set.
- An account that moved to another machine keeps the machines its key made; the admin deleting it there deletes them.
- Taking the key away leaves the account's place where it was: the bots work on this machine until the owner or the admin moves it.
- A bot's own machine costs the owner what a machine costs at boat.dev; that is why going to one waits for the owner's card.
